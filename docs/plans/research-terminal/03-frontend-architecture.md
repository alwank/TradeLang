# Frontend architecture and state

Build inside `apps/web` with the existing Next.js App Router, TypeScript, CodeMirror, Recharts, and generated API client. Reuse result and inspection components through their normal routes. The terminal release can consume the existing contracts and local loopback proxy, including the fields needed for comparison deltas. Preserve the language, worker, run artifacts, and library schema. [Local API routes](../../local-api.md#routes) · [Existing browser milestones](../../implementation-backlog.md#e--mvp-2-browser)

## Routes and state ownership

| Route or state | Owner and behavior |
| --- | --- |
| `/` and `/strategies` | Preserve the current redirect from `/` to `/strategies`. The library is the entry screen for new and returning users. The workspace does not save a landing route. |
| `/strategies/{id}` and existing `?dataset={id}` | Strategy workspace owns the editor and dataset selection. An explicit dataset query wins over transient defaults on entry and follows the existing **Select in editor** flow. Switching strategies exchanges state by strategy ID. Confirm before discarding any unrecoverable edits. |
| `/strategies/{id}?run={runId}` | Proposed in-workspace result route. Retain a `dataset` parameter when present. Keep the same strategy host mounted across ordinary source/result switches and resolve the requested run through the API. Verify that its `strategy_id` matches the workspace before rendering it. A mismatched link can offer **Open standalone run**. Absent or malformed IDs get a usable error and a route back to source. |
| `/runs/{id}` and `/strategies/{id}/revisions/{revision}` | Existing standalone result and executed-source addresses remain canonical and usable from a fresh tab. A run may reference an archived strategy. Render the saved revision read-only regardless of later draft edits. |
| `/datasets`, `/runs`, `/compare?ids=…` | Preserve the current routes and compare selection format. Use the URL for explicit shareable navigation and browser Back and Forward. Carry an optional `baseline` run UUID in the Compare and Change runs links. Keep other view preferences local unless the route already encodes them. |
| Display preferences | Persist a versioned, bounded theme and pane-visibility preference. Use graphite dark and the breakpoint-appropriate pane layout when preferences are absent or invalid. Keep the saved preferences independent of route entry, draft recovery, and immutable run IDs. |
| Editor buffer, caret, and undo | The strategy host owns source and editor state. Keep one CodeMirror instance for the same strategy when alternating between its source and one open run. Hide the inactive panel accessibly, and request an editor measurement after reveal if required. Use normal unmount and cleanup when changing strategy. Test whether same-route query navigation retains the editor in production; if it remounts, move the strategy workspace owner into a stable segment and pass view selection separately. |
| Run view state | Scope selected trade, pagination, event expansion, zoom, and display units to the run ID. Maintain the active result's view state when switching back to source in the same workspace. Mount the charts and bounded result queries only when needed. Reuse the same results view for standalone links. |

Start with one source tab and one open run tab per strategy workspace. The dock can open another run in the result tab. This supports the common loop and keeps mounted charts, editors, and subscriptions bounded. Use links and `aria-current` for URL-driven view tabs and semantic tabs with arrow-key navigation for in-place pane content. Use Back and Forward to navigate previously activated views. Keep the submit action separate from view navigation.

## Request and lifecycle design

1. **Inspection identity.** Record the exact source, primary dataset, and optional profile dataset for each Validate or Explain request. Abort superseded requests and discard results that do not match the active inputs. Keep validation and explanation independent. Use the backend validation hash and compatibility to arm Run for that saved revision and data selection. Current inspection failures and warnings are rendered from the API.
2. **Save.** Retain the current `If-Match` and `expected_revision` update. Capture the submitted buffer when Save starts, and compare the response with the latest buffer when it finishes. A user edit during Save remains dirty. On conflict, retain local text and expose the existing copy and reload options. Validate remains available for drafts and never creates a revision.
3. **Recover a draft after refresh.** Use per-tab `sessionStorage`, keyed by strategy ID and format version, for dirty source and the saved base revision/hash. Debounce writes and flush on safe page lifecycle boundaries. Offer **Restore draft** or **Discard draft** when the saved base is unchanged. If the base differs, expose the recovered text for review or copying and require deliberate user action to use it. Clear only the saved or explicitly discarded draft. When storage is unavailable or full, keep the unsaved-change guard and indicate that the draft could not be cached. Avoid source text in URLs, logs, or persistent workspace preferences. Saved source and runs remain in the local library.
4. **Submit and retry.** Construct the request from the currently saved and validated snapshot of strategy ID, revision, dataset IDs, and gap policy. Allocate a UUID per logical submission. Reuse it across duplicate activation and retries of uncertain outcomes for that request, within the documented 24-hour window. Lock rapid repeat activation before awaiting the API. After a definitive acknowledgement, a deliberate new run gets a new UUID; opening or retrying status for the acknowledged run uses its returned ID. A revision conflict refreshes the known server record and clears readiness while preserving any edits. [Submission contract](../../local-api.md#submit-and-compare-backtests)
5. **Track status and cancel.** Have one polling owner per run ID across the current dock and detail view. Seed it from the submit response when available and poll only the opened run and recently submitted active entries that the workspace displays. Start at one second and back off to five seconds during queued or running states. Stop on terminal state or final unsubscribe. Clear timers and abort outstanding reads on scope changes. Keep the last known status visible through a transient read error, mark it stale, and offer Retry. Acknowledged cancellation and terminal responses outrank older in-flight poll responses. The worker stores an interruption as a failed run with `E_INTERRUPTED`. Display the reason and use the recorded outcome. [Run transport](../../../src/tradelang/api/backtests.py) · [Run persistence](../../../src/tradelang/persistence/runs.py)
6. **Inspect and compare.** Keep paged trades, events, chart envelopes, and exports on the typed client. Each request uses its run ID and relevant filters. Scope comparison to requested run IDs and render the API's alignment and input-difference result. A late response from a closed tab, old run, changed filter, or prior chart range cannot replace the current view. [Result endpoints](../../../src/tradelang/api/run_results.py)

## Comparison state and delta calculation

1. Read `baseline` as an optional single run UUID. Resolve it against the active comparison response. Fall back to the first matched run if the pin is absent, invalid, or removed from the selection. Preserve a valid pin when the user changes the run set, refreshes, shares the URL, or uses browser Back and Forward.
2. Keep the comparison request keyed by `ids`. The server continues to receive only that query parameter. Pinning a different run updates the UI URL and derived values. It can reuse the existing response and the current chart range. Reordering table columns is a view operation. Keep a run-ID-to-response-index lookup for difference arrays, and keep chart color and legend identity tied to run IDs.
3. Calculate deltas from the `ComparisonRun.metrics`, `final_equity`, and `configuration` values already returned. Use the existing incompatible difference fields to evaluate the candidate and baseline entries in the API's original run order. Check matching `first_open` and `last_close_at` for full-run comparability. Use `capital` for the final equity rule and `currency` for display. A missing field needed for eligibility produces a clear unavailable reason. The chart's shared window and benchmark anchor do not replace either run's full bounds.
4. Keep derivation pure and testable. Validate finite raw inputs and format only after subtraction. Show percentage-point deltas as `(candidate - baseline) × 100`, raw integer trade-count changes, and the existing metric precision for quote money, Sharpe, and profit factor. Render a value that rounds to zero as unsigned zero. Include text explaining why suppressed values are unavailable.
