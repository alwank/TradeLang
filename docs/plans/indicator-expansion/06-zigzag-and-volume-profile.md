# Zig Zag and Volume Profile, ranks 37–38

Implement confirmed swing events and a rolling volume-at-price profile. Both contracts distinguish the bar a value describes from the first bar that can use it in a strategy. [Shared conventions](01-language-and-runtime.md#apply-shared-indicator-conventions)

| Rank | Proposed call | Output | First ready index |
| --- | --- | --- | --- |
| 37 | `ZIGZAG(left, right, reversal)` | Price `.pivot`, `.last_high`, `.last_low` and numeric `.direction` | Structural index `left + right`. Each field becomes available when its first qualifying event occurs. |
| 38 | `VPROFILE(n, bin_width, value_area)` | Price `.poc`, `.vah`, `.val` | Structural index `n - 1`. A window needs full child coverage, positive volume, and an eligible price span. |

## 37. Confirmed Zig Zag

Accept each leg length from 1 through 1,000 and an unsuffixed reversal fraction greater than 0 and at most 1. A reversal call such as `ZIGZAG(3, 3, 0.05)` uses a 5% threshold.

1. At row `t`, inspect candidate row `c = t - right`. A high candidate must exceed all `left` preceding highs and meet or exceed all `right` following highs. Mirror the inequalities for lows. Require a complete valid window.
2. Accept the first candidate without testing the reversal fraction. If the first eligible center meets both definitions, accept the high. After a high, accept only a low that is at least `reversal` below the last accepted high, measured against that high. After a low, accept only a high that is at least `reversal` above the last accepted low. If a center meets both definitions once initialized, consider its opposite-side candidate.
3. Emit `.pivot` at confirmation row `t`. Emit unavailable for `.pivot` on other rows. Set `.direction` to `+1` when the last confirmed pivot is a high and `-1` when it is a low. Carry `.direction`, `.last_high`, and `.last_low` forward after each first value. A strategy can detect a later high confirmation with `ZIGZAG(3, 3, 0.05).direction crosses above 0`. The first pivot has no preceding direction.
4. Keep accepted pivots immutable. For an internally invalid sample, clear swing state and require another full window before detecting pivots. Allowed missing timestamps count observed rows. Maintain trailing extrema with bounded queues or an equivalent linear-time algorithm, and verify results against direct centered-window scans.

Test both alternation directions, equality at the threshold, tied highs and lows, a dual-candidate center, and a same-side extreme before the next reversal. Show that the final `right` candles in a dataset cannot serve as confirmed centers yet. Run prefix comparisons with an appended extreme and assert that every earlier output, including unavailable slots, matches. This contract corresponds to causal signal availability. TradingView also supports a chart projection that can redraw a recent pivot. [TradingView Zig Zag](https://www.tradingview.com/support/solutions/43000591664-zigzag-indicator/), [TA-Lib Zig Zag](https://ta-lib.org/functions/zigzag.html)

## 38. Rolling Volume Profile

### Accept a lower-timeframe dataset

1. Add one optional named profile input per strategy invocation. Proposed CLI flags are `--profile-data` and `--profile-metadata`, supplied as a pair along with the primary input. Add a proposed optional `profile_dataset_id` to the existing local HTTP validation and explanation request. Resolve it through the existing dataset resolver. Source-only compilation accepts `VPROFILE` without dataset IDs. Dataset-aware validation, explanation, and backtest report `E402_WINDOW` when a required child dataset is missing or incompatible. Reject a child without a primary input or a child supplied to a strategy with no profile call. An unknown supplied HTTP dataset ID uses the existing lookup error.
2. Load both inputs through the existing candle importer. Use a shared as-of boundary when importing both files in one invocation. Require the same symbol, quote currency, price basis, calendar, volume convention, and UTC bar-open convention. Require a smaller child duration that divides the primary duration, using the existing UTC epoch grid. Allow each input to declare its own gap policy. Pass the secondary input through the common window check and evaluator. Keep fills, positions, and execution timestamps on the primary dataset.
3. Map each child bar to the half-open primary interval `[open, open + primary_duration)` if the child closes by the end of that interval. Require the full child grid for each participating primary row. A missing child inside an observed primary interval makes its profile input unavailable until that primary row leaves the rolling window. A missing primary row contributes no interval or child volume. Ignore child rows outside mapped primary intervals. Determine these masks before computing profiles so a prefix run and its corresponding full-run prefix agree.
4. Carry the child input's canonical dataset hash and role in the run signature and configuration identity for profile runs. Include the child's gap policy in configuration identity, since it lives outside the canonical dataset hash. In the proposed profile manifest version, add a `profile_input` object with the canonical hash, source hash, gap policy, data file, and metadata file. Use `profile-input.csv` or `profile-input.parquet` and `profile-metadata.json` in the artifact inventory. Include the profile input's role and canonical hash in the versioned signature, and keep encoding and raw bytes in artifact identity. Verify the copied child bytes against the imported source hash before replacing the output directory. Apply input and work limits before staging. Remove staging output on failure.

### Calculate the profile

1. Accept `n` from 1 through 256 primary rows, a finite positive literal with a `price` suffix for `bin_width`, and an unsuffixed `value_area` from greater than 0 through 1. A proposed call is `VPROFILE(20, 1 price, 0.7).poc`. Each window includes the current completed primary row.
2. Assign a child candle's entire volume to its close bin. Define bin index as `floor(child_close / bin_width)` using binary64. Bin `b` represents `[b × width, (b + 1) × width)`. If a positive-volume child produces a nonfinite index or an index above `2^52 - 1`, mark the corresponding primary interval unavailable before conversion. Ignore zero-volume children for the bin index span and include them when checking time coverage. Maintain a rolling histogram by adding the newest primary interval's contributions and removing those that leave the window.
3. For a complete window with positive total volume, choose the maximum-volume bin as point of control. If multiple bins tie, choose the lowest price bin. Emit its midpoint as `.poc`. Begin the value area at that bin. Compare the next lower and higher adjacent bins, treating empty bins inside the occupied price span as zero. Include the larger-volume side, preferring the lower side on a tie. Continue until the included volume reaches `value_area × total_volume`. Use the outer lower edge of the resulting area for `.val` and outer upper edge for `.vah`. At `value_area=1`, explicitly use the entire occupied span to avoid rounding-dependent termination.
4. Emit all fields unavailable for a window with a coverage hole, zero total volume, or a price span over 256 bins. A wider bin size can admit the same price range. Publish binary64 output and define bin boundaries by the actual parsed binary64 price and width. Use deterministic accumulation and verify subtraction drift with near-tied bins and repeated add/remove cycles. Avoid interpreting aggregate OHLCV as exact trade-level volume by price.

For a width of 1, suppose bins `100`, `101`, and `102` hold volumes `3`, `6`, and `3`. At a value-area fraction of `0.7`, expect `.poc = 101.5`, `.val = 100`, and `.vah = 102`. The two adjacent bins tie and the lower bin brings cumulative volume to 9 of 12. ### Bound and verify the workload

- Apply the existing dataset size, row, and decoded Parquet limits to each input. Cap the strategy at four distinct profile calls. Repeated selectors and repeated calls with identical canonical arguments share the kernel result.
- Set a proposed preflight cap of 30 million profile work units per invocation. For each distinct call, budget two updates per mapped child row with positive volume plus two visits per bin in each eligible primary window's occupied span. Compute the span from pre-mapped extrema using rolling min and max and exclude windows whose masks already make them unavailable. Count work through the resolved evaluation end, including preceding history. Reject an over-budget invocation before publishing with `E_DATA_LIMIT`. Treat the ceiling and cost estimate as reviewable defaults for this milestone and record benchmark evidence before release.
- Compare a rolling implementation with an independent histogram built from scratch for each window. Cover child-close alignment at an exact boundary, a missing child, a missing primary row, partial warmup, different file encodings with the same canonical child input, price span recovery, zero volume, tie order, fraction 1, and oversized workloads.
- Replay a fixture with both inputs, then alter only an aligned child candle. The child hash and run fingerprint must change. A child candle after the last eligible primary close must leave all earlier signals and profile values identical. Tamper with either copied input and verify that the replay fixture detects the file hash mismatch.
