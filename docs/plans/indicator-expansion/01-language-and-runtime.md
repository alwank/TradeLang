# Language and runtime foundation

Use this document to prepare the compiler, evaluator, and artifact boundaries before exposing the indicator calls listed in the catalog. Signatures, names, and defaults in this plan describe proposed behavior. Example parameters are representative, and callers supply every parameter unless the signature explicitly permits an omitted source.

## Extend the registry and compiler

1. Capture the ten existing functions, their public ASTs, readiness, diagnostic codes and spans, traces, and run digests with the pinned parity corpus. Compare source and candidate with the same Python and dependency versions.
2. Extend descriptors to support fixed `volume` outputs and optional unit overrides per numeric field. Inherit the call's unit for unspecified fields. Keep each field's own readiness callback. Resolve the selected field's type and readiness together during compilation and preserve that type through lookbacks, comparisons, traces, and public JSON.
3. Allow explicit zero-argument descriptors for `OBV()`, `ADL()`, `TRANGE()`, and `VWAP()`. Retain the signature uniqueness, canonical argument order, and input-role validation checks. Use the existing implicit-close normalization for the two forms of a source-taking call. Preserve the previous-period grammar and limits for existing functions.
4. Add narrowly scoped numeric literal roles for the new parameters. Use an unsuffixed decimal literal for offsets, fractions, and factors. Use a positive price-typed literal for volume-profile bin width. Keep semantic parameter validation in descriptors, using `E202_PERIOD` for invalid period and ordering rules and `E203_TYPE` for bad arity, unit, or other parameter constraints. Continue rejecting account-dependent arguments. Use `E204_SELECTOR` for unknown record fields.
5. Add each name to the runtime and published grammar mirrors and the two strategy JSON Schema call enums in the PR that adds its public implementation. Inspect the existing record schema before editing it. Its field map already supports individually typed numeric series, so cover heterogeneous fields with schema tests. Update the integrity test's expected vocabulary and cases, preserving the original ten entries and the pinned parity replay. Add a per-name check that exercises lexing, binding, execution, and serialization.
6. Expose the numeric fields through existing syntax. Use field selection inline or assign the selected numeric field to a `let`. Keep records out of `let` and preserve the existing function and field node layouts.

## Give kernels the data they need

1. Keep function dispatch and caching inside the evaluator. Pass each kernel only the pre-sliced OHLCV columns and metadata it declares. Add read-only integer UTC opening timestamps and timeframe duration for VWAP through the kernel context. Keep those inputs outside the language's numeric candle-field vocabulary. Read timestamps from `Dataset.times`.
2. For VWAP, add a dataset compatibility check when a strategy can resolve a dataset. Use the common compatibility path for CLI run, dataset-aware validate and explain, and local HTTP validate and explain. Run the same check before staging artifacts. Use `E402_WINDOW` for an unsupported timeframe and test the surfaced response for each entry point. Implement the secondary-input checks for Volume Profile in its dedicated milestone.
3. Keep kernel call sharing inside a single evaluator instance. All field selectors from the same call share one kernel result. For each recursive kernel, specify the seed and reset rule. Prefer rolling sums, monotonic queues, or bounded state where they keep the result within the documented numerical tolerance. Use the existing evaluator's expression semantics for logical availability, order scheduling, and risk sampling. Indicator levels used as entry-relative risk distances need an explicit distance expression. Chandelier Exit and Supertrend also work as signal comparisons.
4. Validate output shape, field names, and availability in the conformance harness. Return one finite value or internal `NaN` per bar per field. Count a real arithmetic failure only once per affected result from a unique evaluated kernel call. Count `zero_denominator` only after inputs are ready, when the formula declares the result unavailable, and the computation attempts the division. Distinguish valid neutral outputs, expected sparse outputs, and absence of volume in a profile from arithmetic failures. Preserve the baseline counters for existing functions. Where a state update produces a nonfinite value, invalidate its result and reset state as defined by the kernel. Compare recorded counters through the engine.

## Apply shared indicator conventions

| Topic | Contract |
| --- | --- |
| Structural readiness | Table indices are zero-based for inputs available at row 0. For source-taking calls, add the source expression's readiness. For a record, use the latest field readiness for the record and its own readiness for each selected field. Offsets add bars and crossings need an additional bar. Sparse and data-dependent fields can remain unavailable beyond structural readiness. |
| Windows and gaps | A rolling window includes the current completed row by default. Windows and offsets count observed rows under the allowed-gap policy. When a value is internally unavailable, a window depending on it becomes unavailable until the missing value leaves. A recursive stage clears its state on an unavailable input and restarts from a full consecutive seed. Apply field dependencies independently. |
| Units and scales | Use `price` and `volume` for dimensional outputs. MA, momentum, and regression functions preserve a supplied source unit. Use fractional ratios when `2%` should mean `0.02`. Oscillator points use bare numbers, such as `20`. Keep the existing `W_RSI_SCALE` behavior for RSI. Any future generalized warning needs its own compatibility decision. |
| Literal bounds | Use whole periods from 1 through 10,000 unless a catalog entry gives a tighter bound. Use factors greater than 0 and at most 10 for ATR-based channels and trailing lines, as with BBANDS multipliers. Per-call minima and ordering rules appear with each signature. |
| Seeding | `EMA(x,n)` uses the first complete `n`-value mean and factor `2/(n+1)`. Wilder `RMA(x,n)` uses the same mean seed and factor `1/n`. `TRANGE` emits high minus low on the first valid row of a run, then includes the previous close. DMI and Ultimate Oscillator explicitly require a previous bar for their first sample. |
| Derived quantities | `HL2 = (high + low)/2` and `HLC3 = (high + low + close)/3` refer to candle values. `MAXn` and `MINn` include the current row. `SMA`, `EMA`, `RMA`, and `ATR` in a formula denote kernels or mathematical stages. A formula dependency need only be publicly exposed if the catalog lists it as a call. |
| Divisions and ties | Apply each entry's explicit fallback. Otherwise a complete window with a zero denominator yields unavailable. Use defined equality comparisons and tie rules independent of platform iteration order. |
| Causality | A value at row `t` may use primary data through row `t` and, for Volume Profile, child candles closed by row `t`'s close. Previous input, previous output, and current inputs are distinct stages for recursions. Historical caches and output arrays must be stable when future rows change. |

## Review compatibility before catalog changes

Compare the baseline language aliases, typed projection, published schema validation, result digest, and event-level outputs on existing strategies. Use separate tests for same-build fingerprint stability and cross-build parity. Cross-build fingerprints include the executing package and environment. Keep old run bundles readable under the version recorded in their manifests. Confirm the release's package version and the language, strategy schema, execution semantics, and artifact schema decisions separately.
